# 数学研究导读网站

先选一条读者最想弄懂的结论做样页。从导言走到精确陈述，解释它在整篇证明里解决了哪一步，给一个能手算的小例子，再让读者点回原文。已有 Lean 声明或计算记录时，继续连到对应证据。走通这一条后，再按论文的证明结构扩展章节。

## 从论文组织正文

1. 固定使用的文献版本，从该版整理定理编号、假设、结论、PDF 实际页码和直接前置概念。遇到勘误，写明原公式的位置、修正和核对方法。论文的结论、项目新证明、预印本论证和有限计算各自保留出处与适用范围。
2. 在 `content/registry.yaml` 给每个概念稳定的 `id`，登记标题、摘要、类型、状态、直接依赖 `deps` 和出处 `sources`。检索、依赖图和相关条目共用这些 ID。正文写在 `content/concepts/<id>.md`，用 `[[id]]` 互链。先说明定义或命题的量词，再写直觉、小例子和在主问题中的作用。双语站的译文沿用同一 ID，放在 `content/en/`。
3. 在 `content/book.yaml` 编排教学顺序，每个概念页归入一节。用同一目录生成左侧目录、面包屑、章节编号和上下节。中栏展示原有正文，右栏供读者查本页提纲、依赖、论文和 Lean 条目。保留 `#/c/<id>` 等深链接，读者从图或搜索进入的也是书里这一页。独立投稿的论文稿放在 `paper/`。

## 把结论连到可核对的证据

| 读者想核对什么 | 维护哪里 | 页面怎样使用 |
| --- | --- | --- |
| 原文说了什么 | `content/papers.yaml` 登记文献版本及可提供的 PDF 和 SHA-256，`content/paper-index.json` 将该版定理、公式或章节编号映射到 PDF 页码 | 从概念打开 `#/paper/<id>?p=<页>`，阅读器按页列出相关概念与形式化条目。只有书目信息时展示书目。 |
| Lean 究竟证明到哪一步 | 在 `lean/docs/formalization.yaml` 关联论文条目、声明名、依赖、状态及 comparator 目标。用 `lean/scripts/export_formalization.py` 从源码取出陈述、文件和行号，导出带源码版本的 `lean/docs/formalization.json` | 网站通过 `content/lean-concepts.yaml` 把概念连到声明。逐项显示仅有陈述、已有证明、已由 comparator 认证的范围。一条原文定理拆成多个目标时，逐个核对后再概括整条定理。 |
| 实验具体验证了什么 | 从计算程序导出数据，保留输入、约定、测试范围、输出和可定位的生成程序版本。多语言说明引用同一个案例 ID | 列表展示摘要，详情按需加载原始结果，提供可复算的参数。对同一问题同时展示计算和证明时，注明每份证据各自覆盖的情形。 |

## 复用前端与验收

两个实例使用 Vite 和原生 JavaScript，Markdown-it 渲染正文，KaTeX 排公式，Cytoscape 画依赖图，PDF.js 定位原文。沿用现有站时可复用书页、检索、hash 路由和阅读器。根据新论文重建概念、页码索引和领域算例，同时改写测试中的论文编号、算例假设和语言覆盖范围。需要选择交互形式或排查数据来源时，见[两个站点的实际路径](references/site-examples.md)。

- 内容变更后，在示例仓库根目录运行 `npm run check`，检查概念引用、依赖环、章节归属、公式和译文。变更 PDF 时核对实际文件的摘要，再抽查一个编号在阅读器里对应的页面。
- Lean 源码或登记表变更后，从 `lean/` 运行 `python3 scripts/export_formalization.py` 重新导出，用 `--check` 检查登记内容，在站点根运行 `npm run check:formalization`。要更新认证结论，还要在相应源码版本运行 Lean 工程的构建与对应的 comparator 目标，核对它接受的声明。
- 在 Node 24 下运行 `npm ci`。含 Lean 栏目的版本用 `npm run build`，仅提供正文、原文和算例时用 `npm run build:plain`。两者都运行内容检查，再生成静态 `dist/`。用静态服务打开产物，从目录点进定理，打开原文指定页，再点回概念或已有的 Lean 条目。对改到的功能另外验证语言切换保留当前条目、窄屏目录可用、案例详情实际加载。交付发布任务时，对正式地址上的深链接、PDF 和按需加载的数据重复抽查。
