# 从聊天到日报、周报与 CRM 草稿

适用于用户要求从企业微信工作记录编写报告。以下细节来自原生客户端操作：聊天 AX 读取、CRM 日报草稿填写及重开回读已验证；周报已验证本地归纳，未验证外部周报表单。配置见 setup.md，窗口恢复见 recovery.md。

## 1. 确定范围并保留现场

从已有上下文取得业务日期、时区、是否跳过周末、报告归属人、输出位置及草稿/提交要求。用户随后明确补某个周末日期时，执行该日期；不要顺带扩大其他报告的周期。缺业务信息时按用户偏好留空或标待补，不把猜测写成事实。

先在私有项目保存需求、进度和资料。历史报告用于参考写法，不是新日期的工作证据。比较稿保留原样，独立生成的报告不要覆盖它。

进入 CRM 后按**报告业务日期**检查已提交列表和草稿箱；创建时间可能是补填时间。用户可能在两轮之间提交或修改了草稿，以当前界面为准。已存在同日记录时先读内容，不凭旧进度重复创建。

## 2. 怎样与客户端交互

使用 `mcp__cua_repl` 控制 macOS 企业微信，通过系统可访问性树（AX）取得文字和控件，截图只补充布局及 AX 未暴露内容。这是桌面 UI 自动化；并未取得企业微信聊天业务 API，也不需要读取内部数据库、凭据或私有网络接口。嵌入 CRM 的 WebView 同样可暴露原生 AX，不等于浏览器 DOM 会话。

首次或重置后的入口遵循主 skill，只调用一次 `cua.getApp("com.tencent.WeWorkMac")` 并读返回文档。压缩后恢复既有会话先 `await cua.rewriteDocumentation()`。已有变量不要重复声明。

交互循环：

1. `getAXState()` 识别目标页面、控件和文字；差分不足时使用 `getAXState({disableDiffing: true})`。
2. 对最新状态中观察到的元素执行 `click()`、`scroll()`、`paste()` 或 `pressKey()`。
3. 重新读取，检查实际落点、日期、正文或字段值，再决定下一步。

运行时文档决定参数和输出方法。不要保存固定 AX 索引作为自动化脚本；页面重绘会使索引失效。只有“聚焦同一字段→全选→粘贴→失焦”这类确定序列适合连续执行。日期变更、新增行、客户选择、搜索加载和富文本失焦之后，应重新取状态。坐标必须来自最新截图。

侧栏点击无变化时按 recovery.md 的顶部标签、已验证快捷键及菜单恢复；不能把点击成功响应当作页面已切换。有人同时操作时重新观察。不要并发控制同一客户端。

## 3. 读取聊天与建立证据

先看会话列表中的日期和摘要，定位目标客户、技术支持、内部协作及相关群聊，再进入消息区域。聊天视图可能只加载一段历史；“回到最新位置”可帮助到最新消息，然后向上找日期边界。滚动保留相邻屏重叠，确认移动的是消息区，不是会话列表。滚动条到边缘不一定表示全部历史已加载。

“昨天”和星期名称按客户端当前日期解释，跨日会话逐条归属。一段对话里早期问题与后续解决结果可能属于不同日报，不能全部放进最后一天。覆盖不到的会话或时段明确记录，不称已完整读取所有聊天。

逐会话增量落盘，保留足以复核的证据，建议字段：

| 字段 | 记录要点 |
| --- | --- |
| 来源 | 日期、时间、会话类型及私有项目内可定位标识 |
| 主体 | 用户本人、同事、客户或系统事件 |
| 事实 | 谁做了什么、明确结果是什么 |
| 状态 | 已完成、进行中、提议、待确认 |
| 附件 | 文件名与收发事件；正文是否实际打开读取 |
| 后续 | 明确计划和不确定项，区分推断 |

事实核对时尤其注意：

- 同事发送材料，可写本人协调、收到材料；没有本人转发证据就不写“已交付客户”。
- 收到协议不等于审阅、签署或双方确认。只读附件名不能总结其正文。
- 会议邀请、结束卡片不能证明本人参会或会议结论；明确“你进入了”等事件只支持参与事实。
- 内部估价不等于对外报价；议价、付款提议不等于订单或约定已达成。
- 后续明确的技术澄清优先于此前猜测；不能把疑似数据差异升级成产品缺陷。
- 客户简称只在有可靠映射时关联 CRM 实体；未确认就保留业务称呼、关联字段待补。
- 其他人的一般反馈或系统通知不自动计作本人工作。不要为凑条数填充日报。

原生文档只有窗口外壳时只记“已打开、未读正文”。历史本地归档、当前 AX 实读、截图可见和未读材料分开标注。

## 4. 日报成稿

先读取几份相关历史日报，识别客户明细、内部协作、备注等真实结构。按客户归并当天动作，每条采用“动作→可核实结果/当前状态→必要的下一步”。保留有用技术名词，减少聊天口语，不补造金额、产品或进度。

匿名示例：

> 客户甲：协调技术同事确认设备适配范围，收到说明材料供后续沟通准备；客户所购设备尚未到位，待到位后验证。报价仍在内部准备中。

该表述不能擅自改成“已完成适配、已交付报告并报价”。

内部协作仅填确有事实的内容；没有就留空。无法确认的客户关联、产品、商机阶段、金额等在备注列明待补。空金额不填假零，界面汇总显示零也不能证明明细金额为零。先保存本地最终稿与来源核对结果，再填 CRM。

## 5. CRM 日报草稿填写

实际入口可为“工作台 → 销帮帮 CRM → 行为管理 → 每日工作报告（新）”，以当前页面名称为准。

- **加载和去重：** 草稿抽屉曾短暂显示 `0/20`、暂无数据，随后才加载真实记录；搜索也可能先展示旧候选。依据稳定后的日期和记录判断，不立即创建或选择旧结果。
- **业务日期：** 聚焦可见日期框，全选、粘贴 `YYYY-MM-DD`、Tab 失焦，重新读取确认日期。日期变更可能重绘整个表单，旧索引作废。
- **新增行：** 每次添加后确认实际行数。点击后暂无变化先观察加载，不盲目重试造成多行。
- **行列对应：** 表单 AX 可能按列分组，所有客户框在一起、所有正文框在一起。核对各列数量，按同一表单的明确行顺序对应，不能按 AX 邻近程度配客户与正文。
- **客户选择：** 点击当前行客户空框，取得新出现的可编辑搜索框，输入后读取已加载候选，选择正确全称，检查客户及自动带出的等级。
- **产品选择：** 每行可能有两个 AX 输入节点，一个隐藏的可编辑节点、一个可见占位框。先点可见控件；焦点不对时全选可能选中整页，应停止输入并重新定位。选择后检查标签，`+N` 只能证明有折叠项，未展开不能凭空写出隐藏标签。
- **正文：** 聚焦该行富文本框，粘贴完整多行内容并失焦，再读全文。视觉省略号未必代表 AX 缺字，核对段落句尾和编号。
- **未知字段：** 若草稿允许必填外观的字段暂缺，保留空值；不要选择错误客户或产品来凑完整。若系统确实不允许保存，保留本地稿并准确报告阻塞。
- **内部协作与备注：** 对照本地稿核对勾选项、正文和待补事项，不把上一个日期的字段带入新报告。

## 6. 保存与独立回读

用户要求草稿时选择“保存草稿”，不点“提交”。不因读取或整理任务发送聊天消息。

保存结果不明时先检查草稿列表，避免重复保存或重建。成功提示是辅助证据；即使未捕捉到提示，只要看到新草稿且能重新打开读到完整正确内容，也可确认持久化。

重开目标日期的卡片/容器，核对：

- 报告业务日期和明细行数；
- 每行客户、可见产品标签及正文对应；
- 完整正文、内部协作、备注及保留的空字段。

有隐藏标签未读时如实记录，不称全部标签都已展开验证。发现差异修正并再次回读。无编辑的核验完成后可取消退出。原比较稿保持不变。

按当前 UI 提示记录草稿有效期和关联字段保留期；曾观察到正文草稿与关联产品保留时间不同，不将某次期限推广为所有版本规则。保留本地稿及已确认关联，方便恢复。完成状态明确区分“本地成稿”“已存 CRM 草稿”“已提交”，不能相互替代。

## 7. 从日报归纳周报

以已核对的当周每日证据为来源，按客户串联进展，突出最新状态与遗留问题，不逐日重复粘贴。参考用户既往周报结构；一种已使用的结构为：

1. 本周工作内容：客户分项及市场相关工作。
2. 本周遗留问题/任务。
3. 需要公司重点关注的商机。
4. 需要 AE 及研发重点支持的项目问题。
5. 下周工作计划及建议。

客户数量按真实覆盖决定。标题可覆盖自然周，但正文注明实际工作记录覆盖日期及是否排除周末。后来单独补周末日报，不自动改变已约定的周报范围。下周计划写成计划，有条件的商机保留条件，不将目标变成确定承诺。

本流程已验证到**本地周报草稿与来源核对**。用户若要求保存外部周报草稿，必须先检查实际周报入口、表单、重复记录与保存语义，再按授权填写和回读；不可假设日报字段适用于周报，或将本地文件称为已入外部草稿箱。

## 8. 中断、压缩上下文与隐私

每完成一段来源或一份报告便更新私有项目，不等全部结束。至少保留：来源证据、最终稿、日期/动作主体核对、保存验证和恢复入口。恢复入口记录：

- 已覆盖与未覆盖日期/会话；
- 各报告本地成稿、草稿保存、提交状态，以及最后观察时间；
- 外部用户修改造成的状态变化；
- 当前页面、有效恢复方式和下一步，不保留旧 AX 索引作为操作依据；
- 尚缺事实与人工待补字段。

恢复时先读这些记录，再检查当前 UI，避免重复读取和重复建稿。共享 skill 只沉淀匿名方法；账号、客户、聊天、截图、AX 日志、私有链接和机器路径留在授权的私有项目，不进入共享 Git、提交说明或 PR。
