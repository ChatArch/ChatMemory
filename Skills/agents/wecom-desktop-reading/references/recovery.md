# 窗口与读取恢复

这些现象来自实际客户端操作，不代表每个版本都会出现。先用当前 AX、截图和错误判断问题，再选对应动作；恢复后必须重新识别目标页面。

## 空白主窗口或切到了独立文档

1. 获取完整 AX，避免把差分“无变化”误当成页面为空。
2. 若 AX 有目标页面内容，即使顶层窗口标题为空也继续读取，不要只因标题为空就切走。
3. 若只看到另一个窗口，查看可用的窗口激活动作或原生“窗口”菜单。按已观察到的名称选择目标，不默认选择菜单第一项。
4. 应用级 `getState()` 或应用清单可能不包含全部窗口；不要猜窗口 ID，也不要假设存在未文档化的窗口枚举 API。
5. 需要时通过已识别的“工作台”和业务应用入口重新进入。恢复导航不需要新建日报、草稿或修改表单。

原生文档窗口有时只暴露标题、菜单和窗口控件。此时用截图确认正文是否可见，必要时按重叠区域滚动读取。若截图也无法取到，可使用用户授权且当前确实可用的导出、浏览器或连接器路径；否则说明只打开了窗口，没有获得正文。不要假设浏览器 DOM 工具可以直接接管客户端 WebView。

## 全屏、坐标动作或截图异常

已观察到的错误包括 `noWindowsAvailable`、`Screenshot unavailable` 和 ScreenCaptureKit `SCStreamErrorDomain -3811`。它们不单独证明页面内容不存在或所有读取能力失效。

- **AX 正常但坐标点击失败：** 先用最新 AX 的可操作元素；截图若有效可继续作为布局证据。
- **窗口未激活：** 仅当当前元素提供 `Raise` 次级动作时使用，再获取状态。
- **证据表明处于全屏且坐标持续失败：** 可用已暴露的退出全屏控件。若当前运行时支持且窗口状态已确认，也可用 `pressKey("ctrl+super+f")` 切出全屏。此快捷键会切换状态，不能盲目反复发送。
- **恢复后：** 检查窗口控制按钮和截图内容，重新定位坐标；旧截图坐标失效。
- **窗口右侧超出屏幕：** 如果绿色窗口按钮暴露“缩放窗口”次级动作，可调用后重新截图，确认目标内容进入可见区域。不要假设每个按钮都有此动作。
- **仍然失败：** 重新选择目标窗口，检查是否出现权限或应用提示。若适用恢复路径已失败，不循环发送相同快捷键；请求用户完成一个明确必要动作，并保留已完成数据。

不要把“退出全屏曾修复一次”固化成每次任务都必须执行。

## 点击无变化或详情暂时为空

- 用最新 AX 确认索引。报告日期的文字节点可能不可点击，同卡片的外层容器才是目标。
- 每次只换一个有依据的操作。点击容器后检查目标日期和正文是否实际切换。
- 切换后出现空白基本信息或“无子表单项”时，若仍有加载迹象，观察下一次稳定状态。不要立即归档为空，也不要重新点击造成重复加载。
- 差分输出看不清时获取完整 AX。没有新状态证据时避免无期限轮询。

## 滚动到了错误区域

左侧报告列表、右侧详情、内部表格可能各自滚动。

- 先用截图辨认区域和滚动条，再选择该区域的元素或空白边缘。
- 滚动后用日期、表头、行号或可见段落验证移动的是目标区域。
- 横向 `scroll` 未改变列时，可按当前工具文档拖动截图中真实可见的底部横向滚动条。没有看到滚动条就不要猜坐标。
- 分屏读取冻结列时记录当前报告、分页、行号；恢复窗口或换报告后重新核对，避免把上一份内容配给下一份。

## 恢复结果如何记录

在私有项目进展中记录：阻塞类型、尝试的不同动作、实际恢复证据、完成范围及未读部分。公共经验只保留现象和方法，不复制原始错误上下文里的用户名、窗口私有标题、路径或业务数据。
