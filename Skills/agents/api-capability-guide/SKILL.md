# API 能力与应用认知

先建立可核对的能力目录，再根据用户要做的事情选接口。模型 ID 选择具体型号和版本，接口决定请求形式，工具决定模型能请求哪些动作，应用负责执行与呈现。把这几项同时展示，读者才能判断现有 key 适合接哪些流程。

## 盘点与说明

1. 从当前调用环境确认 provider、官方或兼容 base URL、凭据来源和项目范围。记录配置名与认证方式，密钥留在调用进程或服务端配置中。
2. 调模型列表接口，处理分页，保存抓取时间与完整 ID。将系列、滚动别名、日期快照分别表示。模型接口给出的可见范围，与项目实际完成的调用各自保留证据。
3. 对每个系列建立能力卡，列出输入输出、接口路径、常见用途、最小请求示例、参数或生命周期限制及官方来源。写明哪些说明适用于系列，哪些已经核实到具体型号。
4. 将项目状态记录为已验证的场景、已发起请求但待验收、页面可选或尚未接入。一个图像生成测试只覆盖该次生成流程；编辑、参考图和其他模式继续保留各自的状态。
5. 同时盘点接口和工具。搜索、文件检索、Batch、缓存、结构化输出、函数调用与会话存储，都需要在应用范围里解释。用“做什么、怎么接、目前做到哪一步”组织说明。

## 交付成能理解的应用

让使用页面能跳到所选模型的详情。完整目录支持搜索、系列和验证状态筛选；详情显示精确 ID、版本关系、用途、示例、来源与项目覆盖。接口示例中的模型 ID 跟随当前选择，学习入口本身只做只读查询。

模型目录之外的用量、余额、组织权限、价格和关闭日期分别注明来源与时间。用户已有服务时，先核对它的 provider 适配器、请求协议、模型字段、流式传输和凭据配置位置，再描述可以复用的部分。

## Provider 资料

- 盘点 OpenAI 的文本、图像、音频、Realtime / Live、向量、审核和 Agent 等范围时，读 [OpenAI 能力参考](references/openai.md)。
- 盘点 Claude 的 Models 元数据、Messages、工具与 Agent 执行方式时，读 [Claude 能力参考](references/claude.md)。
- 需要实际派发任务时，按目标 provider 使用 `openai-api-worker-orchestration` 或 `claude-code-worker-orchestration`，保存会话标识并核对实际结果。

共享知识保存通用机制、官方来源和可复用的验证方法。具体 key 可见清单、当前账户余额、真实会话 ID、机器路径及调用记录放在对应项目或本机资料中。
