# 对照与交付验证

验证应回答真实差异。只对当前改动和未覆盖风险补测试，避免反复执行已经充分通过的检查。

## 独立规则差分

优先把原 AS 的可执行规则或独立参考实现放在测试侧，与新 JS 使用相同随机种子、输入序列和时间调度比较状态。参考实现来自固定原件，不能由新 JS 反向生成；必要的语法/API 适配单列，保留原文件哈希。

真实平台运行与测试适配器的差异必须说明。Node 中执行原 AS 的适配版本不等于历史 Adobe Flash；未知调度相位或宿主行为需要原运行观察佐证。

覆盖影响玩法的边界：初始值、计时和帧边界、碰撞、正确/错误输入、随机调用顺序、多个对象同时存在、自然结束与重玩。通过公开输入推进状态，避免仅改内部字段生成“已通关”。需要定位问题时可临时内部探针，但不能把探针结果冒充完整用户流程。

音效测试校验每类对象、动作和原事件的 Sound ID/帧/参数，不能只断言“调用过 play”。规则事件正确后仍需确认浏览器实际解码播放和听感。

## 原版与原生实际比较

固定原件、舞台尺寸和缩放，分别打开原版基准页与原生页。原版可以用 Ruffle，但记录其版本和已知差异，不声称它等于历史 Flash 的全部行为。

逐项记录：

| 场景 | 关注内容 |
| --- | --- |
| 菜单/说明 | 文字、按钮各态、起始音乐和音量 |
| 开局/操作 | 坐标、速度、角色、层级、输入边界 |
| 不同对象/事件 | 分数、动画、对应原声、触发先后、叠加 |
| 计时/关卡 | 自然推进、状态切换、边界和随机顺序 |
| 失败/结束/重玩 | 原结局、清理/保留、分数和声音复位 |

随机画面只能比较相同状态或受控片段；不同随机数帧不能直接用像素差衡量保真。截图保存尺寸、环境与状态，视觉差分关注角色、位置、按钮、文字、层级和色彩。动态声音需要实际播放/录音或受支持的音频分析，静态截图无法证明。

用户反馈某类音效不对时，原版与原生各触发该对象，先核对导出原声、事件日志和参数，再试听；修正后保留该类回归，并检查其他对象是否被同一路由误改。

## 移动端分层

明确分别完成了哪些层级：

1. 布局：竖屏/横屏、DPR、比例、滚动与裁切。
2. 输入合同：真实 app handler 的多指、取消、释放和坐标映射。
3. 浏览器实际触摸：受支持的触摸注入或真实触摸，完整开局/操作/重玩。
4. 物理手机：实际设备、浏览器/系统版本和声音恢复。
5. 目标平台：实际上传或容器打开、SDK/资源限制和平台输入。

手机尺寸截图不能证明触摸通过；handler 测试不能证明浏览器发出了对应事件。工具不支持触摸或窗口失效时，记录具体限制，继续其他独立验证，不编造真机或平台结论。

## 独立包与发布

- 从干净的构建目录生成产物，列出实际文件和 SHA256。检查整个 JS/CSS/资源闭包，含内联、data URL、动态 import、worker 和 source map 可能携带的内容。
- 检查包中没有 SWF/Ruffle/AVM、隐藏字节码加载/解释、测试 oracle/VM 或动态代码执行。字符串搜索只是线索；还要读构建依赖与入口，不能仅凭禁词为零宣称通过。
- 用 HTTP 实际运行，观察 Network 和 Console；关闭外部资源能力或在资源缓存清空的新环境中验证自包含。不要仅用已缓存页面证明断网可玩。
- 保留导出 helper 的许可、必要源码提供方式、原素材来源和版权说明。工具/代码许可与原素材权利分别处理，不能假称提取后素材自动变成开源。
- ZIP 入口与资源使用相对路径；按目标容器检查目录和资源大小。独立包需去除仅网站适用的跳转，保留游戏必须的逻辑和素材。
- 已获发布授权时完成现有部署流程；发布后回读文件/哈希、开局实玩并检查正确原版链接。需要下架旧运行资源时，实际核对旧路径不再可用。不要因本 skill 自动创建网站、DNS、公开仓库或恢复其他游戏。

验收结果建议写成“检查项 → 原件证据 → 新版结果 → 方法 → 未覆盖范围”。最终区分原 AS 差分、浏览器实玩、视觉对照、移动端和平台结论；不能用某一层的成功替代其余层。
