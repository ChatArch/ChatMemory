# Flash 迁移细节

用于处理 SWF 提取、帧动画、精度、碰撞和声音。这里是已遇问题的核对方法，具体数值与行为必须从所选原件取得。

## 离线提取

优先复用项目已有导出及其工具版本、日志和输入哈希。需要新增工具时使用官方项目/发行物，记录实际版本。FFDec 的脚本反编译、XML 标签导出和素材导出互补：AS 文本不包含全部时间轴和按钮信息，静态图片也不能说明规则。

需要取得的内容按游戏决定：

- Header：压缩格式、版本、RECT、FPS、总帧数、AS 类型；加密外壳与内嵌 SWF 分开记录哈希和提取关系。
- AS：根时间轴、MovieClip 帧动作、按钮事件、类定义、宿主初始化及外部 URL。
- 显示列表：Place/Remove、depth、character ID、instance name、矩阵、颜色变换、mask、帧标签、按钮 up/over/down/hit 状态。
- 媒体：原矢量、渐变、位图及其透明度、字体轮廓/静态文本、DefineSound、StartSound、DefineButtonSound 和流式声音信息。

保留可重跑的提取命令与原数据，检查导出工具有没有丢标签或警告。不必把整套导出提交到网站仓库；发布资源的来源映射必须能追溯回保留的证据。

FFDec 可能打印 wrong signature、未生成产物，却仍返回 exit 0 并在末尾显示 OK。导出验收同时检查日志和预期文件：XML 可解析且头部/帧数匹配、脚本或静态 Canvas 文件实际存在且非空、选定 linkage 根及依赖齐全。保留失败日志；不能仅凭退出码或末行文字认定导出成功。

根时间轴的导出不一定带齐仅由 linkage 动态创建的 sprite 位图。合并根/linked 导出时同时合并各自图片与字体依赖，检查生成代码的资源引用、声明和来源表闭包；语法通过并不能排除未声明的图片变量。实际绘制各对象的攻击、受击等状态及可达子帧，不能只渲染 normal 首帧。

部分 Canvas helper 用自维护矩阵恢复离屏滤镜，只包装了 transform/save/restore，未跟踪 translate/scale/rotate。接入新绘制代码时检查实际 helper 的跟踪范围；必要时统一使用等价 transform 矩阵，或完整同步所有变换。只修主画布外观不能证明离屏滤镜也正确，需绘制含该滤镜的完整对象或场景确认。

原 JPEG 被导出为 PNG 时可能显著膨胀。需要缩包时可保留原 JPEG 字节与无损 alpha，但先核对该标签的预乘/反预乘规则；不能直接丢 alpha 或一概用 destination-in 合成。验证恢复 RGBA 后仍应比较完整场景：Canvas 与 Image 作为纹理源，缩放过滤结果可能不同，孤立像素相同不代表最终绘制相同。

旧 JPEG/JPEG3 载荷可能在内部包含 EOI/SOI 分段，不只是文件开头有多余标记。Pillow 能打开不代表浏览器 `createImageBitmap` 或生产 Canvas 解码器能打开；应实际解码全部依赖。浏览器拒绝时优先用可靠导出器无损恢复 PNG，并核对 alpha、完整场景和包体，不机械删除内部标记或使用占位图。

FFDec 26.4 已核对的命令形式如下；其他版本先读帮助。将占位符替换为当前项目路径，导出到独立空目录：

```sh
java -jar "<ffdec-dir>/ffdec.jar" -help -export
java -jar "<ffdec-dir>/ffdec.jar" -export script "<work-dir>/scripts" "<source.swf>"
java -jar "<ffdec-dir>/ffdec.jar" -format shape:canvas -export shape "<work-dir>/shapes" "<source.swf>"
java -jar "<ffdec-dir>/ffdec.jar" -export image,sound,font "<work-dir>/media" "<source.swf>"
```

`shape:canvas` 提供绘图材料，不会自动迁移交互规则。XML/标签、帧与按钮导出按当前帮助选择；避免默认 `all` 批量渲染所有动画导致无必要的时间和存储开销。

## 导出结果需要审查

曾出现按钮仅导出 up 态、透明径向渐变参数错误、文本软换行/对齐差异和裁切范围错误。按原 XML 与实际画面修正，记录修正缘由；不自行补画猜测。

Canvas 转换关注矩阵组合顺序、原点、fill rule、线宽缩放、渐变坐标、颜色变换与透明度。静态缓存或离线图集只能加速绘制，不能改变帧切换、实例状态或碰撞边界。用直接绘制与缓存绘制对照只能证明缓存本身，仍需原版视觉证据。

把导出路径改成 `Path2D` 后，检查所有填充与裁切调用是否也使用缓存路径；压缩函数末尾可能省略分号，按整句字符串替换会漏掉它们。遗漏的原生 `ctx.fill` 可能重用先前遮罩的原生 current path，令后绘对象遮住前面的对象。隔离绘制单个图形可能仍正常，回归应包含真实遮罩之后的多个同类对象及其覆盖顺序。

缓存键应包含影响结果的完整颜色变换（含 alpha 乘数和加数）。直接跳到菜单的截图可能掩盖开场渐隐缓存污染，需走实际开场到菜单的路径。链接 sprite 的导出可能带裁切平移，核对导出坐标的像素/twip 单位后再合入原矩阵。`_visible=false` 也可能由帧脚本设置，不能只读静态颜色判断可见性。

Flash 几何遮罩不能一概用原填充 alpha 作为 Canvas `destination-in` 的透明度；导出器这样处理可能把内容变淡或隐藏。核对所用遮罩类型与原运行，再让几何遮罩绘制通道只表达覆盖范围，保留被遮内容自身透明和边缘抗锯齿。性能检查也要看遮罩是否每帧分配整舞台画布；原已停帧的头像/控件可按完整状态缓存，不必改变逻辑帧率来掩盖绘制开销。

字体嵌入不全、HTML 文本和动态变量绑定可能令实际对齐不同于静态标签。先检查原件和实际显示；现代后备字体与历史 Flash 字体的差异要明确记录。

EditText 绑定需要区分预建的 JS accessor 和原脚本中真实存在的变量。核对构造时已有属性、非空初始文字写回、空初始文字不建变量，以及按钮父级与实际 owner；不能仅用 `field in object` 判定原属性存在。长小数溢出时同时检查原数值转字符串和字段 clip/gutter，不通过舍入游戏变量隐藏绘制错误。

声明了字体名称不代表嵌入了字形；同时检查 glyph/codeTable/advance 与设备字体路径。若目标是匹配固定 Ruffle 基准，可追溯该版本实际 fallback，而不是把字段统一画成系统 Arial。例如 [Ruffle v0.5.0](https://github.com/ruffle-rs/ruffle/blob/v0.5.0/core/src/player.rs) 使用内置 Noto Sans subset；这是该现代基准的选择，不证明历史 Flash 也使用 Noto。保存原压缩字库、解压/子集派生关系、哈希、实际字符范围及许可证；subset 不能声称支持完整 Noto 字库，缺字不能通过删除原文字掩盖。

文字校准分别核对 unitsPerEm、ascent/descent、字号、字段边界与 gutter、基线、对齐和逐字 advance 的量化。固定版本的 [font.rs](https://github.com/ruffle-rs/ruffle/blob/v0.5.0/core/src/font.rs) 与 [edit_text.rs](https://github.com/ruffle-rs/ruffle/blob/v0.5.0/core/src/display_object/edit_text.rs) 可解释设备字形的 twip/整像素舍入；仅有 Canvas `measureText` 相近不能证明原布局一致。用相同 CSS 舞台尺寸与 DPR 的字段截图复核宽度和基线，分开记录来源推算、实际视觉结果及尚未校准的中文/多行路径。必要时离线抽取已许可字库的静态 glyph/advance，不引入 Ruffle 运行依赖。

## 有限绘制缓存与像素范围

整舞台遮罩、滤镜和像素读写的成本取决于实际 backing 尺寸；CSS 尺寸不变时，像素量大致随 DPR 的平方增长。分别记录 CSS、DPR、backing 宽高和同时存活的缓冲；缓存条目的 RGBA 字节预算不等于包含临时滤镜画布的总内存上限。

不可变源位图的完整颜色变换和重复纹理可分别复用；动态滤镜或混合画布不能按原图身份缓存，纹理对象也需区分绘制 context。预算要容纳已测的单场景工作集，并检查连续场景热帧的 miss/淘汰增量；工作集仅略超预算也可能让每帧整组循环淘汰，比不缓存更慢。超大对象应有准入策略。诊断页尽量复用生产实际使用的一套原素材，不为每个样本重复构造整套图片后把垃圾回收、分页或 GPU 压力误判为某一帧的成本。

可把已证有限、静态的滤镜输入分组缓存，先检查完整子树是否含动态帧、按钮、文字或其他状态。Key 覆盖当前画布尺寸、完整变换、globalAlpha、父颜色变换及所有未由组身份固定的输入；不能仅按 symbol ID 合并。准备只绘图，不推进逻辑、timer、声音或 RNG，必要时隔离导出 helper 的可变闭包。进度按实际完成条目推进，组间让出执行；同步单组仍可能有长任务。尺寸变化、取消、失败或超预算应使旧准备失效并清理半成品；完成后只恢复一次待执行动作，不把加载耗时补成游戏帧，也不为菜单缓存暂停正在进行的战斗。

导出 helper 的 JS `_matrix` 与 Canvas 原生 CTM 可能因累计浮点路径不同而微差。不能仅凭矩阵代数等价，把原 `setTransform→drawImage→applyTransforms` 顺序换成 `save/restore`；这可能改变随后图形的抗锯齿。缓存命中路径也需保持经核验的原变换顺序。

核对 helper 实际包装了哪些变换方法。有些 FFDec 版本只跟踪 `transform/setTransform`，原生 `scale/translate/rotate/resetTransform` 不会同步 `_matrix`；自行拼场景时若混用，依赖该字段的描边或滤镜会错位。使用已跟踪的方法，或完整同步后再核原画面，不能仅凭填充位置正常判定正确。

对“mask alpha 选择并替换目标像素”的 helper，优先保持原画布尺寸、绘图原点、路径及渐变，只把读写范围缩至同一整数 ROI；移动整个绘图原点可能改变渐变、细线或抗锯齿。ROI 取变换后的原边界，含线宽和已核边缘余量，并夹入原画布；不要因空交集提前跳过函数后续路径或破坏 save/restore。按相同输入比较优化前后完整像素及按钮 regions，再用真实浏览器复测；少数帧零差不能证明所有状态或所有绘制后端一致。

## 多个时钟与事件生命周期

分别登记 `onEnterFrame`、`setInterval`、主/子帧率、动画帧事件和声音事件。一个游戏可能同时使用 25fps 动画、45ms 运动和 1000ms 时间条；这些值是实例，不能套用到其他游戏。

浏览器 `requestAnimationFrame` 只负责驱动调度和绘制。使用明确的原逻辑步长、累计时间和事件顺序；禁止靠显示器 60/120Hz 自然推进原玩法。后台暂停、积压回调和最大补帧属于环境差异，需要有记录的策略。

源时钟应在开始实现时逐项映射并测试，不能等同速前台运行后才检查：独立 interval/timeout、`getTimer` 墙钟以及基于帧数的动作各自保留。尤其核对迟到回调扣实际经过时间还是固定步长、每次只扣一次还是补齐、重新锚定还是保留余数；不能用“半秒等于15帧”或“3秒等于90帧”替换独立计时器。离线手动时钟也要有迟回调与逻辑帧停顿的合同测试。

已核基准的 ENTER_FRAME 广播按显示对象的首次订阅形成对象桶，同一 Stage 后加入的 listener 仍在该桶内按 listener 顺序执行。不能把所有 listener 按全局添加时间排成一条队列；结合构造/订阅顺序、当前实例与基准调度源码确定相位，再用实际动作核对。

注意构造函数或帧切换可能重复注册 timer；重玩可能留下重复回调。对照源码和原运行结果后再决定是否原样保留，不能出于代码整洁擅自改变可见行为。

原动作中的 `gotoAndPlay` / `gotoAndStop` 可能立即更换当前显示列表。不要把源代码在循环内反复读取的动态图形子属性或命中形状缓存到循环外：第一次命中切帧后，hitter可能已经被移除，下一次源属性查找应得到不存在。缓存旧矩形/旧对象会凭空造成第二次命中。对这类分支，方法oracle要建模当前节点的创建/移除与即时查找，再用明确标注的原SWF同几何fixture核对；只有for循环没有break，不足以认定原版存在多命中bug。

## 数值、坐标与碰撞

- `hitTestPoint(..., true)` 是源几何命中，不等同于最终画面 alpha 采样。核对所选基准的命中选项：某已核 AVM2 `AVM_HIT_TEST` 仅跳过 mask，隐藏子对象与 alpha0 填充仍可能参与。不要因不可见就删除碰撞几何，或用截图的透明像素替代原形状；其他 API/版本另核。
- SWF 坐标以 twip 表示，1 像素 = 20 twip。属性写入、变换、包围盒和 AS 运算并不必然采用同一种舍入路径。
- 先确认 AS 版本和所用 API 的真实精度/强制类型转换；只在确证的边界量化。不要把所有数都统一四舍五入，或仅用 JS 双精度直译。
- 一个已核 AVM2 基准的 [DisplayObject x/y setter](https://github.com/ruffle-rs/ruffle/blob/a4f5b5256e245693bc9077ef6c6b6abc95490e7f/core/src/avm2/globals/flash/display/display_object.rs) 调用 [Twips::from_pixels](https://github.com/ruffle-rs/ruffle/blob/a4f5b5256e245693bc9077ef6c6b6abc95490e7f/swf/src/types/twips.rs)：有限游戏坐标向零截断到1/20像素；普通 Number 速度、加速度仍保留 double。只给显示属性 setter 加量化；独立 AS oracle 的宿主也须采用同一路径，不能让两个 double 直译相互证明正确。其他版本/极值和 NaN 语义另外核实。
- 源普通字段可能撞上原生场景对象的 API，例如 AS 的 `x/y` 缓存与图形对象的 `x/y` getter。离线核对源字段和原生 own/prototype 字段交集，静态区分普通变量与 `_x/_y` 图形属性；用重复 tick 的实际位移检查，避免把缓存写入变成持续移动。不要为解决有限冲突引入通用 AS scope 解释器。
- AVM1 数值强转还受 SWF 版本控制：已核 SWF6 及以下的 `undefined` 转为0，SWF7 起转为 NaN，见固定版本的 [value.rs](https://github.com/ruffle-rs/ruffle/blob/v0.5.0/core/src/avm1/value.rs)。这会改变未初始化计数器与乘法分支；不能一概照搬现代 JS，也不能将一个游戏的版本规则套给另一个。具体 API、比较 opcode 和调用方仍需分别核对。
- 数值运算与显示属性写入需分别核对。例如固定基准的 [stage_object.rs](https://github.com/ruffle-rs/ruffle/blob/v0.5.0/core/src/avm1/object/stage_object.rs) 中，`_xscale` setter 拒绝 NaN 并保留旧属性；源码紧接着读回该属性可能正是恢复旧朝向。普通 JS 字段直接保存 NaN 会让精确对齐后的方向比较与几何绘制失效。AS oracle 的宿主属性也应有正确 setter，并用精确相等、零差、长时间停留及真实输入命中路径覆盖边界；持续偏移目标的等待 fixture 可能避开此错误。
- 实际迁移中曾确认 `_x/_y` 写回向零截断、某些矩阵计算 float32 及边界舍入，累计后影响计时结束。名义秒数不能代替真实时间条计算；不要把某款实测时长写成通用规则。
- 碰撞可能是局部/全局包围盒而非可见轮廓。考虑透明形状、mask、完整父矩阵、旋转/缩放和严格/包含边界，不能随意改成圆形或像素碰撞。
- 对精确规则先做差分；使用有来源的容差。定位到可确证的量化语义后，关键边界应尽可能严格比对，不能无限放宽容差掩盖错误。
- 反编译表达式不一定保持 JS 的强制转换/NaN 分支。例如可读的 `value <= 0` 可能来自 `Greater` 后取反，未定义值时与 JS `undefined <= 0` 结果不同。影响死亡、结算等分支时核对所选原件 p-code 和实际运行，按具体分支迁移；不要仅用反编译文本直译，也不要为一个差异引入通用字节码解释器。

## 子时间轴与状态

同父帧 `gotoAndStop` 不一定重建已存在子实例；父帧不动时子动画也可能继续。每次 render 都新建对象或把子帧归零会改变动画、声音和碰撞。

记录 Place/Remove 和实例存活区间、深度、当前帧、脚本执行点以及重复 goto 的结果。按源行为处理共享实例、遍历顺序、编号循环、帧内销毁和 undefined 值；不要转换成更常见但不同的游戏机制。

同一帧的 DoAction 与 PlaceObject 标签顺序可能改变子 Load/首帧读到的父变量，不能固定为所有子对象先初始化。显式 goto 的早生实例、目标帧新实例、已排队旧帧动作与相同帧 goto 需分别核实。可用固定基准的微型 SWF trace 验证关键语义，但先独立解析 fixture，确认 ActionLength、ClipEvent 位标志和 Stop 正确；无效 fixture 的输出不能作为运行时 oracle。记录静态回调来源帧与执行时实际 playhead，避免错误丢弃已排队动作。

回调顺序可能与创建顺序相关，不能仅按深度排序，或人为固定成“所有炸弹→所有角色”。同一tick新装 `onEnterFrame` 是否立即运行、被同深度新clip替换后的旧引用是否连内建属性都失效，都可能影响连续伤害、死亡后放弹及随机消费。对存在这些路径的游戏实测后保存小轨迹；区分仍有效的局部数值、失效clip属性和整个回调是否中止，不能统一保留或跳过本tick剩余逻辑。

发生销毁的同一 tick，子动画可能先完成最后一帧并消费随机数，再移除父对象；提前清理整树与让已销毁子对象继续运行都会错。相同结果美术也不保证相同生命周期：普通受伤与超时可能分别经完整伤害函数和直接替换，只迁移各分支实际安装的回调、随机调用和后续加分，不因画面相似复用整套处理。

父时间轴循环时，先前被 Remove 的子实例可能重新构造，重新运行帧脚本并消费随机数；只提取首帧随机会漏掉此行为。AS1/AS2（AVM1）中，`attachMovie` 的同名实例可能占不同深度，不能直接用名称唯一 Map 替代显示列表；`swapDepths` 还可能交换已占用深度。按实际编号回绕、重建及交换路径验证。删除 `onEnterFrame` 只取消该回调，子动画仍可能继续，并不等于删除实例。

原键盘状态通常跨场景存在。重玩/结束时是否合成 keyup 应由原行为决定；触屏额外按键则单独处理 pointer 取消与失焦。菜单按钮的按下/释放阶段从 BUTTONCONDACTION 获取，不能按按钮名称猜测。

## 音效逐项溯源

为每个可发声动作建立表，而不只列“提取了几段 MP3”：

| 对象/场景 | 原符号/类与事件/帧 | Sound ID | SOUNDINFO | 原生触发点 | 核验 |
| --- | --- | --- | --- | --- | --- |
| 某类对象被捕获 | 原实例/时间轴帧 | 原 ID | loop/seek/noMultiple 等 | JS 对应事件或帧 | 原 ID/字节/触发日志/试听 |

从 StartSound、DefineButtonSound、AS Sound 调用及子时间轴查映射，不能根据文件名、音长或“成功/失败”语义猜绑定。几类对象可能共享音效，也可能某帧静音；都以原件为准。用户指出听感差异时检查绑定、时机、音量、速率、裁切和叠加，而不只检查资源是否存在。

保留 MPEG payload 与相关样本/seek 信息，避免未经核验重编码。对应处理有限循环次数、in/out point、envelope、noMultiple、stop 标志、`stopAllSounds`，以及离开帧时声音是否继续。没有流式音轨就不要凭空设计流式同步；有流式音轨则不能将其简化为任意一次播放。

空 SoundStreamBlock 或零样本 header 不足以证明没有流音轨，要扫描全部块及其 seek/帧位置，核对时间轴暂停/切换时音轨是否暂停、延续或重启。SOUNDINFO 的 in/out/envelope 位置以 1/44100 秒为时间单位，不能套用 DefineSound 原采样率或 MP3 seek 的单位。AS 调用了某声音名称但 ExportAssets 无对应 linkage 时，先核对原运行；缺绑定的静默不能擅自补声。

仅统计根 `DefineSound` 或根声音导出会漏掉嵌套 sprite 的 MP3Stream。递归遍历每个时间轴的 SoundStreamHead/Head2、SoundStreamBlock 与帧位置；按标签格式分离 MP3 block 的 sampleCount/seek 头（共4字节）和原 MPEG payload，保留每块样本数、seek、采样率、header latencySeek 及所属时间轴。恢复相位应依据原块/stream 的样本时钟，不能直接用采样率除以影片 FPS 代替；暂停、蓄力停帧、循环和恢复各自验证。保留原数据并无损提取，实际浏览器解码与试听另验。

`new Sound(target)` 的 owner 会影响层级音量与 stop 作用域，不能按变量名含“背景”就推断它只影响背景音乐。核对目标 clip、祖先音量合成及 stop 是否递归；例如固定 Ruffle 基准的 [音频实现](https://github.com/ruffle-rs/ruffle/blob/v0.5.0/core/src/backend/audio.rs) 区分 owner 停止与后代音量合成。相同音频字节、原事件与正确的 gain/stop 接线是不同检查项。

浏览器可能丢弃 MP3 起始延迟或附加 padding，解码后的裁切需要结合原参数和实际结果验证。原菜单与游戏音乐可能叠加，不能擅自换成独占播放。自动播放限制由用户手势恢复 AudioContext，不改变之后的原触发关系。

网页新增的声音开关与原时间轴 stop 分开处理。若开关语义是静音，可用输出总线保留既有源时钟；不能 stop 所有源后重开从头播放，或丢掉只在首帧触发的流。首次中途启声时，只恢复原脚本仍有效的音轨余段，依据该游戏实际时钟与暂停规则记录起点；原 stop、死亡、移除、切场景或替换必须清理恢复记录，避免复活旧音轨。单一音轨用单一状态即可，不为此引入通用播放器。

相同 MPEG 字节仍可能因解码器、整数/浮点量化及重采样不同产生听感差异。实际比较先固定输出采样率，再对齐 PCM 并核对起音、结束、循环边界、音量和包络；相关系数不能单独代替试听。若确有差异，可离线生成有来源的普通 PCM/WAV 再验证，保留原 payload 与派生关系、依赖许可，不因此引入游戏运行时播放器。Web Audio 采集应排除用于解码的 OfflineAudioContext，并把同一真实 context 的多个输出汇合后按一条时间轴采集，不能把各输出块串接成错误时长。

区分“事件第一次实际派发”和“已在播放的循环恢复相位”。不要把渲染回调迟到的时间直接当成新短音效已经播放的时间，否则会切掉起音甚至漏播；同时检查实际播放区间内的 noMultiple，而不是只用理论事件时间计算抑制区间。

## 宿主与服务依赖

搜索 `_parent`、`_root`、ExternalInterface、getURL、loadVariables、Socket 和加载外部 SWF 的路径，区分：

- 本地即可完成的玩法。
- 宿主提供的启动参数或关卡数据。
- 账号、分数上传、兑换等外部功能。

通过原脚本/调用方证据还原必要输入。旧服务不可用时给出明确边界；不要伪造提交成功、重写服务响应，或在缺少必需数据时宣称完整迁移。

## 保护壳、真实脚本版本与可达声音

- 外层只有很短加载脚本、却带很大的 `DefineBinaryData` 时，先读 `Loader` / `ByteArray` 操作，按字面算法离线解包与解压；不要执行未知保护器来取素材。分别固定外壳与内载荷的签名、长度、版本、SHA，原件始终保留。
- 一个 `DoABC` 不足以证明真实玩法是 AS3。保护器可能混入只会退出或无限分配的假类，使导出器遗漏实际 `DoAction`。交叉检查版本、FileAttributes、各动作标签数量及加载链；不能把保护代码当游戏规则。
- 只有确认属于保护层的阻碍标签，才可在**分析副本**中最小移除以暴露脚本，并记录每个标签的偏移、原字节与删除后SHA。副本只供逆向，原版浏览器基准仍走原始加载链；分析副本能导出脚本不等于它能独立正常游玩。
- 声音标签、链接名或 `sound.play()` 文本不等于实际有声音。核实 Sound 实例是否构造、音库片段是否可达、帧动作是否执行，再用原件实际播放验证。原件变量未赋值或音库不可达时，不按设计意图补音乐或音效；未确认的可达性明确留待核对。
