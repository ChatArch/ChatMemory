# Formal Docs, i18n, And PR-History Cleanup

## What Triggered This Reference

During ChatGH docs alignment, the user corrected two important documentation-quality mistakes:

1. Default Chinese MkDocs pages included English-only prose, while English pages were handled as separate nav entries or fallback content.
2. Formal docs used implementation-history language such as `第一阶段`, `第二阶段`, `本轮落地范围`, `Implemented Scope In This PR`, and `MVP`.

The durable lesson: a ChatArch docs PR should produce formal package documentation, not a progress report.

## Correct Shape

- Chinese default pages (`docs/*.md`) contain Chinese prose.
- English mirrors (`docs/*.en.md`) contain English prose.
- English proper nouns, command names, API paths, status literals, URLs, and code identifiers may appear in Chinese pages when they are literal interface names.
- `nav` lists only default-language pages; `.en.md` files are mirrors generated by `mkdocs-static-i18n`, not separate nav items.
- Formal docs describe current capabilities, planned capabilities, scope boundaries, command contracts, and safety rules.
- PR bodies, `progress.md`, and changelog entries may describe what changed; formal docs should not narrate the PR history.

## Bad Formal-Doc Patterns

Avoid headings or prose such as:

- `第一阶段`, `第二阶段`, `第三阶段`
- `Phase 1`, `Phase 2`, `Phase 3`
- `本轮落地范围`
- `Implemented Scope In This PR`
- `Following this PR...`
- `MVP` when the document really means `最小可用能力` / `Minimal Usable Capability`
- `first version` / `first pieces` when the document really means `outside current scope`

## Preferred Rewrites

| Progress-style wording | Formal-doc wording |
|---|---|
| `第一阶段：repo 命令族` | `当前仓库命令` |
| `第二阶段：PR 生命周期` | `当前 PR 命令` |
| `第三阶段：Actions run` | `当前 Actions 运行命令` |
| `本轮落地范围` | `当前 CLI 到 Python API 映射` |
| `后续优先补` | `规划中的能力` |
| `不需要一开始实现` | `不属于当前范围` / `不属于最小闭环` |
| `最小 MVP` | `最小可用能力` |
| `Suggested command surface` | `Planned command surface` or `Command Plan` |

## Verification Pattern

After `mkdocs build --strict`, run the skill script from the repo root:

```bash
python /path/to/skill/scripts/check_doc_language.py
```

Expected successful signals:

```text
english_source_cjk_count: 0 equivalent
chinese_source_full_english_count: 0 equivalent
formal docs contain no progress/history labels
English generated article bodies contain no CJK
```

If the script flags a command example like `status=in_progress`, do not blindly translate the literal. Instead decide whether it is an actual interface literal. Literal interface values may remain; progress-history headings and prose must be rewritten.
